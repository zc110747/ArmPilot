## 1. 结论一：舵机 → 关节的角色映射（**已确证**）

```
S9 -> base      （底座偏航）
S7 -> shoulder  （大臂 / 下臂）
S8 -> elbow     （小臂 / 前臂）
S6 -> gripper   （开合）
```

固件里的 `left / right`（`MeArm-Device/bsp/servo.h` 的命名）只是**物理安装位**称呼，
**不等于运动学角色**。按它分配肩/肘会得到反向的机构 —— 这是本次修正的一处真实缺陷。

### 证据 A · 扫 S8 时"画面最高点"零位移

`tools/analyze_sweep.py` 输出的「塔顶（掩膜最高点）」：

| 扫描 | 舵机 30 → 100 | 塔顶位移 |
|------|---------------|----------|
| **S8** | (603,220) → (595,220) | **≈0 px（全程 (594±4, 221±2)）** |
| **S7** | (570,220) → (736,321) | **194 px，且下沉 101 px** |

扫 S8 时画面最高处**纹丝不动** ⇒ S8 驱动的不是整条臂，**S8 不是肩**。
扫 S7 时整条臂的上端一起走 ⇒ **S7 是肩**。

### 证据 B · 公共静止区自动分段（`tools/segment_arm.py`）

「扫某个舵机时始终为暗的像素」= 该舵机管不到的部分，于是可以直接把机构拆开：

```
inter_S7 = 扫 S7 全程不动 = 底座 + 立柱（含线材）
inter_S8 = 扫 S8 全程不动 = 底座 + 立柱 + 大臂
=> 大臂 = inter_S8 − dilate(inter_S7)
=> 小臂+爪 = 某帧掩膜 − dilate(inter_S8)
```

`inter_S7` 25198 px、`inter_S8` 31540 px —— 后者多出来的 6342 px 正是**大臂**
（面积占比也符合"大臂在两帧里都不动"）。

### 证据 C · 逐帧目视（`analysis/g2_S8.png`，3×2 网格）

S8 = 30/45/60/75/90/100 六帧并排：**大臂（那对斜板）角度逐帧完全一致**，
只有肘端往下的那一段在摆。这是"肘"的定义图像。

### 采集中踩到的两个坑（结论用）

- `arm_ang`（塔顶→爪尖的连线角）在扫 S7 时只变 1.6°。**这不能当作"小臂解耦"的证据**：
  刚体旋转本来就不改变任意两个刚体点之间的连线方向。第一版据此推出的结论方向对了、
  但推理是错的，本文改用下面的双参数拟合重做。
- 「离枢轴最远的暗像素」做爪尖跟踪**不可靠**：夹爪是两片薄板 + 阴影，帧间会换身份。
  实测扫 S7 的"圆周拟合半径"折合 47 mm，比大臂 80 mm 还短 —— 物理上不可能，
  说明跟踪点已经跑到阴影上去了。**因此放弃单点跟踪**，改用整条骨架对掩膜的对称 Chamfer。

## 2. 结论二：小臂是**绝对角**（平行四连杆解耦）（**已确证**）

### 做法 · `tools/fit_pose.py`

1. 白底分割 → 机械臂掩膜 → 倒角距离变换 `DT`；
2. 把模型的 3 段连杆（大臂 80 / 小臂 80 / 手部 40 mm）在矢状面内投影成折线骨架；
3. 目标函数 = **对称 Chamfer**：
   `mean(DT(骨架点)) + mean(最近骨架点到掩膜点的距离)` ——
   前项把骨架压进掩膜内，后项防它缩成一小段（只做前项会退化，因为掩膜很厚）；
4. Hooke-Jeeves 模式搜索 5 个参数：`s`(px/mm)、肩枢轴 `(ox, oy)`、肩角 `ths`、小臂绝对角 `the`；
5. 覆盖项先**剔掉底座/立柱区**（用上面的 `inter_S7` 膨胀），否则拟合会被底座大团拉偏。

### 去耦判据（扫 S7，舵机 80 → 155，共 75°）

用 **RESET 帧（`S8_090.jpg`）锚定**像素尺度与肩枢轴（`s = 2.626 px/mm`，肩枢轴 `(591.8, 463.6)`），
再逐帧放开 `ths` 与 `the` 两个参数：

| S7 舵机 | `ths` 肩角 | `the` 小臂**绝对**角 | 相对角 = the − ths |
|--------:|-----------:|---------------------:|-------------------:|
| 80  | −2.91° | 112.47° | +115.38° |
| **90** | **+0.85°** | **112.62°** | +111.78° |
| 95  | +4.94° | 112.38° | +107.44° |
| 110 | +14.76° | 113.86° | +99.10° |
| 125 | +23.87° | 115.97° | +92.10° |
| 140 | +34.31° | 119.85° | +85.54° |
| 155 | +50.00° | 122.55° | +72.55° |
| **Δ（80→155）** | **+52.91°** | **+10.08°** | **−42.83°** |

**判据**：

| 假设 | 预期 | 实测 | 结论 |
|------|------|------|------|
| 小臂**绝对角**基本不变 | Δ绝对 ≈ 0 | **+10.08°** | ✅ 成立 |
| 小臂**相对角**基本不变（普通串联关节） | Δ相对 ≈ 0 | −42.83° | ❌ 不成立 |

⇒ 肩关节摆 52.91° 时，小臂的绝对倾角只漂 10.08°。**小臂角与肩角解耦**，
真机由独立舵机经**平行四连杆**驱动（连杆参考系挂在底座侧，而非大臂侧）。

### 模型表达

`config/robot.yaml` 里 `elbow` 关节写：

```yaml
coupling:
  joint: shoulder
  gain: -1     # 串联网里的局部旋转 = the + (−1) × shoulder
```

即 **`elbow` 关节存的是绝对倾角**，FK / Three.js 渲染都经
`effectiveJointAngle()`（`frontend/src/robot/kinematics/fk.ts`）取用，两者逐值一致。

> **已知残差（诚实声明）**：实测漂移 10.08° 并非 0。若按残差硬拟合，
> 等效增益 = `10.08 / 52.91 − 1 ≈ **−0.81**` 而不是理论值 `−1`。
> 模型取 `−1`，因为这正是"平行四连杆"的机构本义，而 10° 落在本次拟合的
> 残差（≈25 px ≈ 9.5 mm）之内。**下一次实测（见 §5）应重测这一点。**

## 3. 结论三：标定增益与零位（**实测反解**）

`tools/fit_pose.py` 用 RESET 帧锚定后逐帧求解，得到「舵机角 → 关节角」序列。

### 小臂 S8（6 帧，舵机 30 → 100）

| S8 | 30 | 45 | 60 | 75 | **90** | 100 |
|----|----|----|----|----|--------|-----|
| 小臂绝对角 | 135.70° | 133.33° | 127.53° | 120.29° | **112.62°** | 107.63° |

线性拟合：`the = −0.4177 · servo + 150.69`，最大偏差 2.47°
⇒ **增益 0.4177 关节度/舵机度 ⇒ `scale = 2.39401`（reverse）**

### 大臂 S7（7 帧，舵机 80 → 155，含 RESET 锚点）

| S7 | 80 | **90** | 95 | 110 | 125 | 140 | 155 |
|----|----|--------|----|-----|-----|-----|-----|
| 肩角 | −2.91° | **+0.85°** | +4.94° | +14.76° | +23.87° | +34.31° | +50.00° |

线性拟合 slope 0.694 关节度/舵机度（**注意增益非线性**：低角段 ≈0.55，高角段 ≈0.80，
典型舵盘连杆特性；线性模型是折中）
⇒ **`scale = 1.44018`（非 reverse）**

### 写入 `config/robot.yaml` 的值

| 关节 | 舵机 | offset | scale | reverse | 关节限位（= 舵机硬限位反算） | 舵机硬限位 |
|------|------|-------:|------:|---------|------------------------------|------------|
| `base` | S9 | 90 | 1 | false | −60 … +60 | 30 … 150 |
| `shoulder` | S7 | 88.776 | 1.44018 | false | −6.0936827341 … 49.454929245 | 80 … 160 |
| `elbow` | S8 | 359.61 | 2.39401 | **true** | 108.4414852068 … 141.8582211436 | 20 … 100 |
| `gripper` | S6 | 40 | 1 | false | 0 … 90 | 40 … 130 |

**自洽性**：把 `homePose` 的四个关节角代回标定式，恰好得到 90°（固件开机位）：

```
base     :   0        × 1      + 90    = 90.000
shoulder :   0.849894 × 1.44018 + 88.776 = 90.000
elbow    : -112.618577 × 2.39401 + 359.61 = 90.000
gripper  :  50        × 1      + 40    = 90.000
```

### HOME（= 固件 RESET 位）的物理姿态

| 关节 | 值 | 物理含义 |
|------|----|----------|
| `base` | 0° | 指向正前方 |
| `shoulder` | **0.8498937633°** | 大臂轴线仅前倾 0.85°（照片拟合值） |
| `elbow` | **112.6185771989°** | 小臂**绝对**倾角：离天顶 112.62° ⇒ **前下方 22.62°** |

⇒ HOME TCP = `(111.96, 0, 93.84)` mm（`x = 80·sin(肩) + 120·sin(小臂绝对角)`，
`z = 60 + 80·cos(肩) + 120·cos(小臂绝对角)`）。
虚拟臂渲染出的 RESET 姿态与 4 张实拍照片目视一致（见 `docs/images/armpilot-console.png`）。

## 5. 下一次实测要做什么

> ⚠️ **2026-09-13 更新**：本节第 4 条（改 `coupling.gain`）已被 §5.2 判定为**作废**
> —— 在测量本身不可复现之前，任何"改模型 / 改标定"的取值都是猜。
> 下一步的**唯一**入口是 **§7 的台面重测流程**（含锁变量清单与可执行的判据命令）。

1. **加标尺**：在画面里放一把钢尺（或打印棋盘格），把 `s` 从"拟合出来的"变成"量出来的"，
   这一步能直接消掉绝对角的系统性偏差。
2. **正交取景**：相机光轴尽量垂直于机械臂运动平面（现在是斜看），减少透视压缩。
3. **覆盖全行程**：S7 扫到 80/160、S8 扫到 20/100 的**硬限位端点**，
   验证增益在高角段的非线性，并确认 `ACTUATOR_REACH` 反算的限位端点。
4. **重测解耦残差**：在**固定 S8**的前提下扫 S7（本次已如此），
   若绝对角漂移稳定复现 ≈10°，就把 `coupling.gain` 从 −1 改到实测值（≈−0.81）。
5. **校核连杆长度**：量大臂/小臂/手部的轴孔中心距，替换开源标称值。

## 5.1 复测记录 · 2026-09-12 19:25（Phase 9 真机闭环）

本次借 Phase 9 的 `tools/verify_serial_e2e.mjs` 端到端跑批（7 帧，真串口 + 相机），
**复现了 §2 挂起的四连杆解耦残差**，并顺带否掉了「换 ROI 能提精度」的假设。

### (a) 四连杆耦合增益残差**复现**（这是主误差源）

`verify_pose.py` 的标定增益复核（Δ关节反解 / Δ舵机，对比 `robot.yaml` 的 `1/scale`）：

| 通道 | 实测 | yaml | 偏差 |
|------|------|------|------|
| S7 肩 | +0.93 | +0.69 | **+34%** |
| S8 肘 | −0.21 | −0.42 | **−50%** |

表现是**乘性过冲**：命令小步（+5°）时误差 ~0.5°，命令大步（+15°）时误差涨到 **+4~11°**：

| 帧 | 意图肩角 | 拟合肩角 | 差 |
|----|---------|---------|-----|
| `01_sh_p5` | 5.71° | +6.71° | +1.00° |
| `02_sh_p15` | 16.13° | +20.59° | **+4.47°** |
| `05_combo` | 16.13° | +19.73° | **+3.60°** |

**目视复核**（`.workbuddy/captures/e2e_*/overlay/02_sh_p15_fit.jpg`）给出机制：
绿色骨架贴合的是臂的**外轮廓边**，不是中心线 —— meArm 的"小臂"是**两根平行杆**
（平行四连杆），`verify_pose.py` 的三连杆骨架**在结构上表达不了它**，
于是被厚轮廓的一侧吸住 → 角度虚大。

> **结论**：这与 §2 的记载**完全一致** —— `coupling.gain` 实测应 ≈ **−0.81** 而非 −1。
> 想提精度必须**改骨架模型表达四连杆**（而非调阈值/ROI）。
> **这正是 §5 第 4 条的待办，本次予以确认。**

### (b) ROI **不是**限制因素（否掉一个假设）

用户要求「用新 ROI 更新数据」。流程与结论：

1. `tools/measure_roi.py` 量出臂紧包围盒 → 数值上像是 `(0, 87, ~510, 349)`（半分辨率口径）；
2. **目视复核否掉**：`x0=0 / x1=1279` 是 **USB 线缆横穿 + 桌沿暗带**，不是臂；
3. 单批（`e2e_192500`）实验：新 ROI `(150,170,1010,690)+--base-anywhere` 把锚点偏置
   从 −2.20° 改善到 **−0.45°** —— 看起来很美；
4. **跨批交叉验证否掉**：

| 批次 | 旧 ROI `(330,150,1040,530)` | 新候选 `(150,170,1010,690)` |
|------|---------------------------|---------------------------|
| `e2e_191514` | 偏置 −4.27/−3.67，各帧\|err\|均值 **6.29** | 偏置 −5.06/−3.96，均值 **12.17**（明显变差） |
| `e2e_192500` | 偏置 −2.20/+0.44，均值 **4.14** | 偏置 **−0.45/+0.20**，均值 4.48（略好） |

⇒ **单批"变好"是对该批的过拟合**。**结论：维持旧 ROI 不变。**

### (c) 批间锚点偏置不稳定（≈2°）**不是**曝光漂移

两批曝光几乎相同（整图中位 145 vs 148；背景 `y<150` 中位 169 vs 172；均 0% 过曝），
但锚点偏置差 2°。两批 RESET 帧相减 → **整幅画面所有边缘都亮**
（亚像素整体位移/轻微失焦的典型特征，非形状变化）⇒ **取景在两批之间整体挪动过**。

⇒ 再次印证：**绝对角跨批不可比；同批内「重复性」才是可信指标**
（本批肩 0.89° / 肘 0.00°；§4 旧批 0.26~0.31°）。

### (d) 方法学教训（写给下次）

- **量包围盒必须目视复核**：线缆/桌沿会污染 bbox，只看数字必错。
- **定 ROI/阈值必须跨 ≥2 批验证**：单批最优 = 过拟合。
- **脚本退出码 1 ≠ 崩溃**：`verify_serial_e2e.mjs` 的 `1` 是"验收 FAIL"，
  已加日志（`run.log`）与顶层 `.catch()`（打印堆栈、区分 exit 2/1）以便分辨。

## 5.2 A1 判定 · 2026-09-13（骨架改双杆 + 跨批可复现性）

**假设**（来自 §5.1 (a)）：meArm 的小臂是**两根平行杆**，而 `fit_pose.py` 的三连杆骨架
用一条折线代表它，于是被厚轮廓的一侧吸住 ⇒ 角度**系统性虚大**。
若假设成立，把骨架改成**双杆**就应当消除这个偏置。

**做法**：把"改模型"从"凭 §5.1 目视结论直接改 `robot.yaml`"降级为**可判定实验**，
新增两件工具（都不是新的测量，只是把已有的判据固化成命令）：

| 工具 | 作用 |
|------|------|
| `tools/verify_pose.py --rod-gap MM` | 骨架小臂按 `rod_gap` 画成两根平行杆（0 = 原单折线，向后兼容）；`--selftest` 新增**自检 C**：真值按双杆渲染，模型分别用单杆/双杆拟合，**在不依赖任何实拍照片**的前提下量出"模型表达力"这一项的贡献 |
| `tools/verify_calib_repro.py` | 打印「批次 × 底座掩膜 × 骨架模型」的增益散布矩阵，并写死判据：**极差 ≤ 5% 才允许据偏差改模型** |

### (a) 自检 C（合成真值，隔离"模型表达力"）

| 杆距 | 单杆 Δ肩 | 双杆 Δ肩 | 单杆 Δ肘 | 双杆 Δ肘 | 改善（肩/肘） |
|------|---------|---------|---------|---------|--------------|
| 0mm | — | — | — | — | 逐值退化为同一模型（向后兼容已验：w2_S7 仍报 `+0.6033 / −13.1%`） |
| 4mm | — | — | 2.00° | 1.74° | +0.26°（肘） |
| 8mm | — | — | — | — | **方向不一致**（肩 +0.76° / 肘 −1.97°） |

⇒ **无单调趋势，改善量在 0.3° 量级**，与 §4 记录的 ±5° 绝对角不确定度相比可忽略。

### (b) 实拍 `--rod-gap` 矩阵（0 / 4 / 10 × 5 配置）

| `rod_gap` | w2_S7（base-anywhere） | w2_S8 | dir_S7（底座掩膜 `self`） |
|-----------|----------------------|-------|------------------------|
| 0 | −3.7% | +0.9% | −2.3% |
| **4** | **+0.7%**（"修好了"） | **−0.5%**（"修好了"） | — |
| **10** | — | — | **−46.3%（拟合退化）** |

`rod_gap=4` 在两个配置上看起来"正好修好"；但杆距只稍大到 10mm，`dir_S7` 直接崩到 −46.3%。
**同一组参数在不同配置上既有"修好"也有"崩掉"** —— 这是过拟合的典型形状（与 §5.1 (b) 的
ROI 教训完全同构）。

### (c) 最终判定（`tools/verify_calib_repro.py` 输出）

```
================ 标定增益跨批可复现性矩阵 ================
elbow      偏差范围 [+0.9%, +53.8%]  极差 52.9%  (容差 5%) ⇒ 先锁台面，禁止据单点结论改模型
shoulder   偏差范围 [-13.1%, -2.3%]  极差 10.8%  (容差 5%) ⇒ 先锁台面，禁止据单点结论改模型
⚠️ 有 2 个组合的 |偏差| > 40%：拟合在该配置下退化
结论：至少一个通道的跨配置散布超出容差 ⇒ 测量本身不可复现，
      此时把偏差归因给骨架模型或标定表都是不成立的。
```

**结论（与 §5.1 的原始假设相反）**

1. **A1（改骨架双杆）不是精度问题的解**：单杆模型在 `--base-anywhere` / `dir` 批次下
   本就接近真值，双杆"改善"只在特定配置出现、且 `rod_gap` 稍大即退化。
   ⇒ **`robot.yaml` 不动**；双杆能力作为工具保留（默认 `rod_gap=0`）。
2. **A2（把 `coupling.gain` 从 −1 改到 −0.81）作废**：`gain` 是 `config/robot.yaml`
   的**唯一直值源**，会同时影响前端 FK / IK；而当前测量不可复现，任何取值都是猜。
3. **真正的短板是测量可复现性**（台面 / 相机 / 曝光 / 底座掩膜未锁死）——
   这与 §5.1 (c)、D39/D40 一脉相承。**下一步只能是重新上台面测量**，
   且判据已固化为可执行命令（见 §7）。

> 教训一句话：**"改模型让它对上"和"调参数让它对上"是同一类错误**；
> 必须先证明"测量对得上"，才有资格谈"模型对不对得上"。

## 7. A3 台面重测步骤（2026-09-13 交付，待操作者执行）

> 本节是**留给操作者的交付物**：代码与自检已就绪，缺的只是"锁死台面后重测一遍"。
> 目标不是"把误差调到 0"，而是先拿到一份**跨批可复现**的测量。

### 7.1 前置：把变量锁死（这一步决定了后面所有结论是否成立）

| # | 动作 | 为什么 |
|---|------|--------|
| 1 | 机械臂与桌面之间铺**白色分割板**（灰度 < 90 = 机械臂） | 底座掩膜靠它；换板 = 换批次 |
| 2 | 相机用三脚架固定，**在底座与镜头座上各贴一个标记点**，拍一张"基准照" | §5.1 (c)：整幅画面在批间挪动是绝对角不可比的根因 |
| 3 | 曝光**手动锁定**（关自动曝光/自动白平衡），记下光圈/ISO/快门 | 虽然 §5.1 (c) 证明它**不是**那次 2° 偏置的原因，但锁定它才能排除该变量 |
| 4 | **USB 线缆移出画面**，或固定在不会随臂摆动的路径上 | §5.1 (b)：线缆横穿会污染包围盒与轮廓 |
| 5 | 相机光轴尽量**垂直**于机械臂运动平面（侧视正交） | §5 第 2 条；斜视会让透视压缩进角度 |
| 6 | 画面里放一把钢尺（或打印棋盘格） | §5 第 1 条：把 `s`（px/mm）从"拟合出来的"变成"量出来的" |
| 7 | 确认串口可用：`python tools/mearm_hw.py ping`（COM 口按 `config/robot.yaml`） | 采集脚本会在单进程内完成 [复位 → set → 稳定 → 抓拍]，避开 DTR 复位陷阱 |

### 7.2 采集（**两个批次**是硬要求）

```bash

$PY tools/mearm_hw.py sweep 7 80 95 110 125 140 155 --out-dir .workbuddy/captures/a4_S7
$PY tools/mearm_hw.py sweep 8 30 45 60 75 90 100   --out-dir .workbuddy/captures/a4_S8
```

### 7.3 判定（**唯一允许改模型的入口**）

```bash
# ⓪ 先把新批次登记进 tools/verify_calib_repro.py 的 BATCHES（脚本按"批"组织，
#    每批 = 一个「相机位 / 曝光 / 台面」组合；锚点帧一律取该批的 RESET 位）：
#
#    BATCHES = [
#        {"key": "w2",  "label": "w2（台面 A）", "s7": "w2_S7",  "s8": "w2_S8",
#         "anchor": "w2_S8/S8_090.jpg",  "base_region": None},     # None = 沿用默认
#        {"key": "dir", "label": "dir（台面 B）", "s7": "dir_S7", "s8": "dir_S8",
#         "anchor": "dir_S8/S8_090.jpg", "base_region": "self"},   # 换相机位后必须 self
#        {"key": "a3",  "label": "a3（锁台面 · 批次 1）", "s7": "a3_S7", "s8": "a3_S8",
#         "anchor": "a3_S8/S8_090.jpg", "base_region": "self"},
#        {"key": "a4",  "label": "a4（锁台面 · 批次 2）", "s7": "a4_S7", "s8": "a4_S8",
#         "anchor": "a4_S8/S8_090.jpg", "base_region": "self"},
#    ]

# ① 跨批可复现性 —— 这是本次重测的主判据
$PY tools/verify_calib_repro.py                      # 默认只跑已登记的 w2 / dir
$PY tools/verify_calib_repro.py --only a3            # 登记后按 key 单跑
$PY tools/verify_calib_repro.py --spread-tol 5.0     # 极差容差（百分点），默认 5.0
```

| 判据 | 通过 | 不通过 |
|------|------|--------|
| **增益跨批极差** | **≤ 5%** | 先继续锁台面（回到 7.1），**不得改模型/标定** |
| 单批拟合 \|偏差\| | ≤ 40% | 该配置拟合退化，先查锚点帧与掩膜，别读数值 |
| 重复性（同批内重复同一帧） | 角残差 ≤ 1° | 检查线缆是否入镜、是否有手入镜（D40） |

### 7.4 只有 7.3 全绿才允许做的事

- 把 `robot.yaml` 的 `coupling.gain` 从 −1 改成实测值（预期 ≈ −0.81）；

> 三条只能**逐条单独**改，每改一条就重跑 7.3。一次改多条 = 无法归因 = 白测。
