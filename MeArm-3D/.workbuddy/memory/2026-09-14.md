### 关键发现（写进 `docs/architecture/*.md`）

- **渲染层与 FK 共用 `effectiveJointAngle()`**（`buildRobotObject3D.ts` 直接 import 自 `fk.ts`）
  ⇒ 这是 Phase 3 能到 8.7e-14 mm 的根因，也是抽象层**绝不能复制该函数**的理由（风险 R1）。
- **抽象层"顺手修正语义"会让回归失去意义** ⇒ 所有适配器写成纯字段搬运；
  唯一一处故意严格：`toIkOptions()` 对未知 `prefer` **显式抛错**（`ik.ts` 会静默退化为 `elbow-up`）。
- **`orientationError: null` 而非 `0`**：本机无姿态自由度，填 0 会同时骗过调用方和测试。
- **`defineRobot()` 是视图（对象同一性成立），`forward()` 是新构造结果（只能比内容）** ——
  我一开始用 `toBe` 断言 `forwardKinematics()` 的返回值，2 项失败；改为 `expectSameNumbers()` 逐位比对。
- **`joint.type === 'revolute'` 才是"可动关节"的唯一规则**（不是 `!== 'fixed'`），三端同源。

## 首帧"重影"根因定位与修复（D74 · 首次接管握手）

- **用户报告**：网页**首次加载**时机械臂显示重影/阴影，按 HOME（或任意命令）后消失。
- **取证方法**（截图抓不到瞬态，两条都用上了）：
  1. 两张用户截图先做**平移对齐**（互相关搜 dx/dy，`meanAbsDiff 0.003→0.350`），
     再取残差 —— 残差集中在臂部（`>30` 的 8727 像素）本身就排除了"整页差异/相机移动"。
     ⚠️ 第一次裁错区域（按 1080 缩略图裁，原图 1907 宽）⇒ 残差假性为 0，差点得出反向结论。
  2. `TestProbe.tsx` 加**逐帧记录器**（`SceneFrameSample`：每帧 `roots` / 每棵树 `ghost·visible·tcp`），
     `tools/first_load_probe.mjs` 直连 CDP 取 `window.__armPilotFrames`。
- **假线索**：frame 0 读到幽灵 `tcp=[0,0,0]` —— 是 `useFrame` 先于 `gl.render` 的**仪器伪影**
  （主臂那帧正确，只因 `RobotArm` 每 0.25s 显式 `updateMatrixWorld`）。**不是** bug。
- **真根因**：`commandJoints` 初值 = `robot.yaml` 的 `homePose`，这是**对机器现状的假设**；
  后端 sim/mujoco 开机都在 HOME，所以"页面刚打开"这个条件**不够**，必须先把后端挪走：
  新增原语 `tools/park_sim_pose.mjs`（把 sim 停在指定位姿，**不硬编码限位**，位姿由调用方给）。
  复现后读到：主臂 tcp `[115.033,0,109.224]`（=FK(HOME)）vs 幽灵 `[108.203,0,112.334]`（=机器现状），
  持续 31 帧不收敛 ⇒ 那棵半透明的第二棵树就是"重影"。
- **★ 最严重的后果不是画面**：命令侧仍是假设的 HOME ⇒ 首次下发（哪怕只动 1° 滑杆）会把
  **整组角**发下去 = 真机从现位置一记跳变扑向 HOME。**修复的价值主要在这里。**
- **修法**：`robotStore.attachToActual()` + 桥在**首次** `connected` 置 `attachPending`，
  由**第一帧回推**消费；**不下发**（`suppressCommandSend`）、**让位于用户意图**
  （`commandAuthoredSinceConnect`，这条护栏是被 mock 闭环 4 项失败逼出来的），
  重连仍走 D32 的"补发命令"。稳态回推**照旧只写 actual**。
- **验收**：tsc 0 error · vitest **351/351**（26 文件）· vite build 探针 0 命中 · go test 5 包 ok ·
