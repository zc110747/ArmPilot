## 11. ⚠️ 工具层教训：同一文件的并发 `Edit` 会**静默丢更新**

收尾时生成了界面截图，发现**页头仍显示 `Phase 1–7`** —— 而我明明改过它。排查后确认：

**把针对同一个文件的 2 处以上编辑放进同一条消息（并行 tool call）时，每次 Edit 各自"读→改→写"，
后写者整体覆盖先写者的结果，而两次调用都报 success。**

本轮实测两例（都在本轮内部就已埋下）：

| # | 丢失的编辑 | 被谁覆盖 | 症状 |
|---|-----------|---------|------|
| 1 | `robotStore.ts` 新增 `teachTrack` / `teachRecording` **初始状态** | 同批的 action 实现编辑 | `tsc -b` 报 `missing the following properties from type 'RobotStore': teachTrack, teachRecording`（幸好 tsc 抓到了） |
| 2 | `App.tsx` 的 `Phase 1–7` → `Phase 1–13` | 同批的 `<TeachPanel />` 挂载编辑 | **完全静默** —— tsc / vitest / build / e2e 全绿，只有截图看得出来 |
| 3 | `TeachPanel.tsx` 的 notes 文案清理 | 同批的 import 清理编辑 | 静默（残留 `` {`${50}ms`} `` 这种怪写法） |

**判据（改完立刻查）**：并行改同一文件后，`grep` **逐个**确认目标字符串都变了。
`tsc -b` 能抓出"接口声明了但初始值没加"这一类；**但纯文案/JSX 的丢失只有截图或 DOM 断言能发现**。

**修法（已写进 `~/.workbuddy/MEMORY.md`）**：**一个文件一次 Edit，串行提交**；
只有**不同文件**的编辑才可以并行。本项目后续所有编辑按此执行。

> 顺带：截图脚本传 POSIX 风格路径给 Windows 上的 Node 会落到 `<当前盘>:\e\cnb\...`
> （`/e/cnb/...` 被当成"当前盘根下的 e/cnb"），必须传 `E:/cnb/...` 或反斜杠路径。
