## 一、唯一真值源与铁律

- **模型 / 标定 / 限位 / 零位的真值只有一份**：`config/robot.yaml`。前端与 Go 后端**都读它**
  （`hello` 带限位/标定做在线互检）。**禁止在代码里硬编码尺寸 / 角度 / 限位。**
- `backend/config.yaml` **只放运行参数**（端口 / 设备模式 / 模拟器参数），**禁写限位与标定**。
- ★ **真值已冻结（2026-09-13，用户要求）**：`config/baseline-kinematics-physics.json` +
  `tools/freeze_baseline.py` + `tests/sim/test_baseline_frozen.py`。
  **判据是「语义核心哈希」不是整文件哈希**（D55）——
  改**外观**（`links[].geometry` / `details`：尺寸 / 颜色 / 细节件）**放行**，
  改**运动学**（`length` / `joints` 轴限位耦合 / `actuators` 标定）或**物理量**
  （gravity / contact / timestep / servo / inertia）**报错**并逐字段列出差异。
  有意识地改参数后：`$PY tools/freeze_baseline.py --update`
  **并且**重跑 `python simulation/mujoco/gen_model.py`（否则 MJCF 与配置脱同步）。
  > 推论：**外观层完全自由** —— 几何 primitive / 颜色 / 未来的照片纹理与重建网格
  > 都可以随便迭代，运动学与物理被钉死。这是做视觉建模的前提。
- **外观层（视觉）的两条实测铁律**（做任何贴图/建模前必读）：
  1. **plate 的大面法向 = `size` 里最小那一维**。`[22,5,74]` → 大面 22×74、法向 **±Y**；
     `[94,82,7]` → 法向 ±Z。
     ⚠️ **2026-09-13 实测定论（推翻本条的旧说法）**：大臂/小臂板大面法向是 **±Y**，
     摆动平面却是 **X–Z** ⇒ **相机必须放在 −Y 一侧（垂直于摆动平面 ≈ "站侧面"），
     当前机位本来就是，不需要做任何转向**。旧说法"转 base 90°"错两处：
     ① `base` 限位**只有 ±60°**（超了后端直接拒），② 转向对分辨率是**零和**（见 §六·五）。
  2. **`RoundedBoxGeometry` 的 UV 是"每面各自铺满 [0,1]"、与长宽比无关** ⇒
     不能整块挂一张图（会 6 面各显示一遍且非等比拉伸），必须**按面用材质数组**。
     实测 6 个 group 覆盖全部顶点，`materialIndex`：`0=+X 1=-X 2=+Y 3=-Y 4=+Z 5=-Z`。
- **照片纹理链路**：`docs/texture-capture-guide.md`（拍摄清单，文件名权威清单是
  `python tools/make_texture.py --list`）→ `raw/` → `tools/make_texture.py` → `tiles/`。
  ⚠️ **禁用 PIL 的 `Image.transform(QUAD)` 做透视校正**：它会引入 +12~17px 的**静默**平移
  （D56，已加源码扫描测试防倒退）。用 `make_texture.py` 里的 `homography` / `_warp`。
- **第二份真值（MuJoCo 轨）**：`config/physics.yaml` **只放物理量、全 SI**；
  运动学量（长度 / 轴 / 限位 / TCP / HOME）**一律从 `robot.yaml` 读**，有测试盯着
  （`test_config_truth_is_not_duplicated`）。改 `robot.yaml` 后**必须重跑
  `python simulation/mujoco/gen_model.py`** —— `mearm.xml` 是**派生产物**，
  有 `test_generated_mjcf_is_in_sync_with_config` 盯同步（会打印 diff）。
- **`mode`（simulation/real）不是 UI 开关**，它决定"要不要发给真实机械臂"。取值必须**校验通过才改**，
  失败要 pushLog 说明**为什么**和**怎么修**（拒绝不是目的，让用户知道在驱动谁才是）。见 D41 / D43。
- **机器人相关状态一律进 store**，组件不持局部副本（含 `teachTrack`）。理由之一很实际：
  e2e 探针要读原始数值，组件内状态只能读 DOM 的格式化文本。

## 三、测试与探针纪律（血泪换来的）

- **探针只准用 `matrixWorld` / DOM 层真实现象做证据，不许把数学再算一遍**：
  用 `FK(actual)` 证明"渲染了"是自证（挂错树 / 可见性误关 / 全透明都会让断言全绿）。
- **探针（含 `delete window.__xxx` 那一行）必须 `import.meta.env.DEV` 守卫**，
  否则字面量进生产包（D27 起的固定检查项）。
- **时间相关的多个读数必须合并在同一次 `cdp.evaluate`** —— 分两次 CDP 往返会让快收敛的量读到归零值，
  变成**间歇性失败**。
- **不许用推导量当独立判据**：`TransportStats.moving = lagDeg > eps`，用它判"卡死"永远得不到结论（D44）。
- **没有正面证据不下断言**（如"卡死"）：宁可停在保守态（`tracking`）。

## 四、测量与标定方法论（D37 / D47）

- **单批"最优" = 过拟合**。定 ROI / 阈值 / 骨架模型**必须跨 ≥2 批验证**。
- **"改模型让它对上"与"调参数让它对上"是同一类错误**。必须先证**测量可复现**
  （`tools/verify_calib_repro.py`：增益跨批极差 ≤5%），才有资格改 `robot.yaml`。
- **一次只改一条**，每改一条重跑判据；一次改多条 = 无法归因。
- 量包围盒必须**目视复核**（线缆 / 桌沿会污染 bbox）；**手入镜 / 相机位移**是头号污染源（D39/D40）。
- ★★ **带区间的搜索必须显式检测"最优解是否贴边"**（D59 ①，代价惨重）：
  最优落在区间端点 2% 以内 ⇒ **该值不是测量结果，是区间的人为截断**。
  实测 `project_plates.py` 的 `s = 3.80` **恰好等于当年的 `S_LO = 3.8`**；
  放宽到 `×0.6~1.8` 后最优变 **2.58** —— 两次"测量"互相矛盾，而按 3.80 出的三块纹理全不合格。
  **这比"分数不高"隐蔽得多**：分数看着还行、数值看着合理，实际毫无意义。
  判据：**两个读数互相矛盾时，先查区间是不是设窄了，别急着改模型。**
- ★★ **纯几何推理走不通时，改用「致动并观察」（motion-diff）**（D59 ④）：
  动一个关节 → 拍前后两帧 → 差分 ⇒ **差分区域 = 该关节及其下游零件**，
  完全不依赖任何相机/位姿假设。这是"哪个像素属于哪个部件"最可靠的答案。
  实测：shoulder/elbow/base 各改变画面 **19.9% / 14.3% / 16.1%** 的像素；
  用「随 shoulder 变 **且** 不随 elbow 变」成功筛出大臂板（x≈622–706）。
  ⚠️ 但**给不出干净的单板四角**（肩座/平行杆/线缆连成一片）⇒ 只做**归属判定 + 粗定位**。
- ★ **「无位置回读」≠「没动作」**：MG90S 没有位置反馈，只说明**不能证明"到位"**，
  **不等于"没动"**。差分给了正面证据（三个关节各改变画面 14~20%）。
- 当前状态：A1（骨架双杆）/ A2（`coupling.gain` → −0.81）**均判定为不改**；
  下一步唯一入口是 A3 台面重测（`docs/hardware-measurement.md` §7）。

## 五、能力边界（必须在文档与 UI 里显式声明）

- **MG90S 无位置回读**：`OK SET` / `STATUS` / 后端 `joint_state` **全都在说"我打算去哪"**，
  没有一条能证明"它实际上在哪"。串口回执**原理上无法验证物理到位**，唯一外部地面真值是**相机**（D34）。
- 因此 Phase 11 误差面板反映的是**链路时延与限位截断**，不是"物理臂到位没有"；
  Phase 12 幽灵臂证明**链路走通了**，不证明物理到位。

## 六·五、图像采集与判定（照片纹理轨 · D56 / D57）

- **采集闭环**：`tools/capture_texture.py`（抓帧 → 三态判定 → 动作建议）→
  `tools/make_texture.py`（透视校正 → 纹理）。判定工具**降采样**（只判几何），
  纹理必须用**全分辨率**原图。抓帧取**最后一帧**（设备启动会吐黑帧）。
- **★ 三态判定 `ok` / `reject` / `undecidable`。「判不了」≠「不合格」** ——
  臂板由螺栓连成一体，"最大的暗色连通域"永远是**整条臂**。此时**禁止**输出任何
  "看起来像结论"的数字（第一版打了"12 px/mm"与"差 182%"，看着都挺真，人照着调一天也没用）。
- **★ 局部轴 ≠ 世界轴**：plate `size` 的最小维是**局部**薄轴，映射到哪个世界轴取决于位姿。
  `upper_arm/forearm_link` 的局部 Y → 世界 Y（侧面拍）；但 `forearm_brace` / `tool_link`
  的局部 Z → **世界 X（沿臂伸出方向）**。⇒ **别背轴向，拿实物转一圈找面积最大的面**。
  坐标系基准：`base` 关节轴 = 世界 Z、`shoulder`/`elbow` = 世界 Y ⇒ 摆动平面 = **X–Z**。
- **★ 指标要量在正确的对象上**：清晰度不能量板**内部**（均匀黑板对不上焦也是 0）
  ⇒ 量**轮廓**梯度；且必须**归一化**：`ramp_px = ΔI / (2·斜率)`，理想硬边 = 1.0。
  绝对值会被**光照**缩放（真机帧 ΔI 仅 119；亮场景同一条边斜率翻倍）。
  实测：真机 1.17 · 模糊 r=1 1.8 · r=2 3.1 · r=3 4.6 ⇒ 上限 2.5。
- **★ 真机臂板是镂空桁架**，`geometry.size` 只是**外接盒**（可透过开口看到背后的墙）；
  前端渲染成**实心** `RoundedBoxGeometry` ⇒ 照片纹理**必须做孔洞掩膜**，
  否则把背景色烘进孔洞、比不贴更假。填充率低（40~50%）是**提示**不是**阻塞** ——
  升级成阻塞会让每张真机照都判死，工具变噪音源 = 等于没有工具。
- **硬件上限**：本机 `Integrated Camera` 只有 **1280×720**（`ffmpeg -f dshow` 直取，
  无需 OpenCV）。相机上限与 `px/mm` **只由物理距离决定**（见下）。长边**横放**顶到画面边前能再靠近 1.78 倍。
- **★★ 动关节改变不了 `px/mm`**（2026-09-13 实测定论，本轮最重要的结论）：
  - **`base` 旋转对分辨率零和** —— 远端放大 ×1.08 但板法向偏 20°、投影缩短 `cos20°=0.94` ⇒ **净 1.015**，
    还白搭一层透视。**转 base 是纯亏。**
  - **肩/肘摆动同样不改 `px/mm`**：摆动平面 X–Z **平行于像平面** ⇒ 不改距离、不改投影长度，
    只改板**在画面内的朝向**。三证：仿真倾角 89.2°→79.2°→59.2°→41°（长度不变）·
    真机 HOME vs `shoulder=30` 暗色面积 236345→230804（**−2.3%**，来自遮挡）· base 净 1.015。
  - ⇒ **唯一手段是物理靠近相机**。`s` 现由**三个独立方法收敛到 `≈3.7–4.1`**
    （旧 CALIB 3.80 · 修正手性后的整臂剪影 IoU 4.05 · 梯度吸附后按长宽比反推 4.2~4.4，D61 三）。
    ⚠️ 中途得到的 `2.58` 是**欠定下的假解**，不是测量值（D59 ① 只对了一半）。
- **★★ 「白卡隔离出单块板」不成立**（推翻本条旧说法）：
  实测暗像素占整帧 **25.7%**（左下象限 65%）；板、立柱、底座、舵机、控制板**全是同一种黑**，
  板与板**由螺栓物理相连** ⇒ **不存在"只含一块板"的连通域**（最大域占 97.7%，bbox `x[0,1040] y[0,690]`）。
  **白卡挡得住背景，挡不住结构性连通。**
- **★★ 目标板四角 = 模型投影给初值 + 图像梯度吸附**（`snap_quads.py`，D61 五）。
  单靠投影不够（整臂剪影 IoU 只 43% ⇒ 误差几十像素），单靠目视也不够（±15px，板与关节块连成一片）；
  **两者合起来可行**：投影给"大致位置与走向"，梯度吸附（沿四边采样梯度幅值取最大）给"像素级贴合"。
  实测边分 8.78→**19.30**（大臂）/ 4.65→**18.74**（小臂），且**长宽比精确吻合真值**
  （大臂 96.2×323.7px = **3.37** vs 3.36；小臂 75.8×286.4px = **3.78** vs 3.78）。
  ⚠️ 用此法前**必须先确认手性**：模型与实拍互为**镜像**时 IoU 永远上不去（30.2% → 修正后 **43.2%**）。
  仍有效的旧教训：`project_plates.py` 三项相乘目标函数**欠定**（只优化"框内暗色"时 `s=2.5`
  把三块板挤进左下底座暗区拿到 **97.4% 假性满分**，`oy=770` 已在画面外）；
  投影时**必须排除 `table_top`**（约 1m 见方，会撑成全屏矩形使 IoU 退化成"实际面积占比"）。
- **⚠️⚠️ `mujoco.Renderer(model, height, width)` —— 参数顺序是 (height, width)**（D61 一）。
  我全程按 `mj.Renderer(m, 640, 360)` 传 ⇒ 实得 **640 高 × 360 宽竖幅**，再按横幅贴片/裁剪
  ⇒ **所有渲染对照图都是拉伸/裁切的**，并由此得出两条**错误结论**（均已撤回）：
  ① "azimuth=270 与实拍一致" → 正确是 **90**（此前模型是**镜像**的）；
  ② "模型几何与 3D 打印实件有系统性差异" → **渲染伪影**。
  ⇒ **工具调用的参数语义必须先验证**：传反不报错、不告警，却会让下游每条目视结论都错，
  而且错得"看起来很有道理"。同类：离屏渲染本机上限约 320×180（见 render_fix.py）。
- **★ 线缆不在板面上（更正 D60 四）**：4× 放大后看清橙色线缆在板的**背面**，
  是从**三角镂空里透出来**的 ⇒ 上一轮"线缆悬在板前、软件无解、必须物理拨开"**过强**。
  真正的问题是**四角把镂空区一起圈了进来**。⇒ **不需要动物理**。
- **★ 残留问题 = 语义不匹配 —— 已解决（D62）**：实板是**镂空桁架**，模型 `*_vis` 是**实心 box**
  ⇒ 纹理里的"孔洞 + 透出的背景"烘到实心盒上会把背景色带进去，比不贴更假。
  ⇒ 出路是**孔洞掩膜**（把非板面区域填成板面材质），已落地在 `tools/make_texture.py`（默认开，
  `--no-fill-holes` 可关）。**三层判据缺一不可**：
  ① **连通性** —— 亮区**接触纹理边界** ⇒ 填（板外）；**被板面完全包围** ⇒ 再按面积定
  （小 = 螺栓保留，大 = 镂空填）。★ 纯亮度会把板面上的**螺栓一起填掉**。
  ② **形状** —— 保留的亮斑还须 bbox 填充率 ≥ 0.60 且长宽比 ≤ 2.0。
  ★ 只判面积会把被暗区包围的**线缆小段**也留下（实测大臂纹理左下多出一块橙色残留）。
  ③ **色差** —— `R − B > 15` ⇒ 填。★ 暗线缆的**亮度低于阈值**（中位 32 vs 阈值 60），
  只判亮度**永远去不掉**它。实测板面 `R−B` 中位 −19/−16、p90 −8/−10，与暖色分得很开。
  ★ **填充色必须取实测板面中位色 `RGB(1,1,20)`**（近黑**带蓝**，不是纯黑；填 (0,0,0) 有色差补丁）。
  ★ 实测纹理亮度**双峰**：板面峰 0~20、非板面峰 110~125、中间 30~90 是谷 ⇒ 阈值 60 落在平台上。
- **★ 判据只有在其前提成立时才有意义（D60）**：`project_plates.py` 的 `ramp`（边缘过渡）
  是在**投影框边缘**测"暗↔亮"过渡的 ⇒ 框定位错了它就成噪声：实测误报"失焦 10.78px"，
  放大目视真实边缘仅 **~2px**（并未失焦）。⇒ **不要拿下游指标反推上游前提。**
- **★ 纹理质量的上限由物理条件决定（D60）**：必须同时满足 ① 目标板**完整入画**
  ② 目标面**正对相机** ③ 板面**无遮挡**。
  ⚠️ 旧条目里的"③ 不被线缆横穿"**已更正** —— 线缆在板**背面**，不构成遮挡（见上）。
  其余 7 块板（`base_link` / `column_link` / `column_link_side` / 两 brace / `tool_link` /
  `jaw_link`）在单个姿态下**被遮挡或不在视野**，需要额外姿态/机位逐一补拍。
  已有纹理：`forearm_link` / `upper_arm_link` —— **填孔后已入库**（填入 33~35%、暖色残留 0.00%、
  亮像素仅 0.85~1.25% ⇒ 近黑底 + 几枚螺栓亮点）。
- **★ 判「四角贴合吗」只有一条定义上无歧义的判据：纹理四条边的亮比例**（D62）。
  框精确贴合板 ⇒ 四条边全落在板上 ⇒ 应接近 0。实测 `upper_arm` 上 45.2 / 下 18.5 / 左 31.1 / 右 46.4%、
  `forearm` 上 57.6 / 下 33.7 / 左 61.5 / 右 19.7% ⇒ **框比板大约 30%，两块板偏心方向还相反**。
  ⚠️ 早先的"框外 / 镂空"二分统计**不能单独判贴合** —— 镂空若开口到板端，同样接触纹理边界
  而被算进"框外"（**两种解释都能套上同一个数**）⇒ **该换判据，不是换参数**。
  ⚠️ 但四角偏差**不阻塞**：板面近黑（亮像素 <1.3%）、可见内容主要就是那几枚螺栓
  ⇒ 照片纹理这条路的**边际收益主要在螺栓高光与表面细纹**，与"直接给一个黑色材质"差别可能不大
  ⇒ **先贴上去看效果**，再决定要不要继续投入（而不是继续抠四角）。
- **真机链路**：`backend/bin/armpilot-backend.exe -c config.serial.yaml` ·
  **COM16 USB-SERIAL CH340 @115200 8N1** · 开机 `STATUS S6..S9 全 90(H)` = HOME。
  调试入口用 `tools/set_joints.mjs`（`--status` / `--home` / `name=value`），别拿验收脚本当摇杆。
  ★ **`hello` 里没有 `connected` 字段**（`protocol/serial-v1.md` §5.1 写了，属**文档漂移**）
  ⇒ 判"是否真机"只能 `hello.device === 'serial'`。
  ★ **`hello` 与 `joint_state` 同时到达且 `hello` 在前** ⇒ 发送点必须在收齐 `joint_state` 之后，
  否则"保持不变"的关节会 fallback 到 `homePose` = **把臂拉回 home**。
  ★ `--settle` 的"保持不变"会让状态**跨实验累积** ⇒ 对比实验必须先 `--home`。
- **★★ "自动定位目标板走不通"这个结论只对了一半（D59 → D61 更正）** ——
  走不通的是**纯目标函数搜索**（欠定）与**镜像下的 IoU 配准**，**不是**"投影定位"本身。
  真正的解是**投影给初值 + 梯度吸附**（见下条），且前提是**手性正确**。
  已确认无效的旧路：① 三项相乘目标函数（只优化①时 97.4% 假性满分）；
  ② 放宽区间后最优 score 仅 18.2，叠加图三个框都没贴板边。
  ③ 三块板在 HOME 位**竖直首尾相接**（立柱 Z[38,60] 紧接大臂 Z[59.8,134.2]）⇒ 单条边无法唯一定位。
  ⇒ 出纹理用 `snap_quads.py` 的吸附结果喂 `make_texture.py --corners`，**一律目视复核**。
- **★ 取景：HOME 位臂会被画面顶边裁掉**（`y=0` 处 x[506,760] 连续暗带）
  ⇒ **不要在 HOME 位出纹理**。改用 `shoulder=45` 这类姿态：整臂完整入画、
  且板面仍正对相机（肩/肘绕**世界 Y** 摆动 ⇒ 板的大面法向 ±Y 不变）✓ 实测可行。
  ⚠️ `project_plates.py --capture` 的 `CONCLUSION` 里 **`ramp` 不可信**（见上），
  只看"投影范围 vs 画面"（是否出画/被裁）即可。
