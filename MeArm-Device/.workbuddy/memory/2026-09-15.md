## ⚠️ 本轮踩到的 .bat 内核级坑（值得沉淀，已写进 skill）

1. **`for /d %%d in ("路径\前缀*")` 的 `%%d` 会带上外层引号**
   → `%%d` = `"C:\...\dir"`。任何 `if exist "%%~d\x"` 都失败（引号进路径）。
   必须 `set "X=%%~d"` **去掉引号**再判存。本轮 TOOLCHAIN_DIR 为空就是这个原因。

2. **`for /f "delims=;"` 无法把"分号拼接字符串"切成多行**
   → delims 切的是**行内 token**，不是行。拼成一个变量再读出来必然塌成一行。
   正解：`MISSING_1..N` + 计数器（cmd 没有数组的惯用法），
   `if defined M1 set /a N+=1 & set "MISSING_!N!=!M1!"`。

3. **`call :label` 在 `if (...)` 块内 / 标签在调用点之后 → 失败**
   → 报 `系统找不到指定的批处理标签`。cmd 对 call 标签按**文件镜像**解析。
   本轮改为：helper 放中段，主流程 `goto :after_helpers` 跳过，**在块外** `call`。

4. **`if/echo` 里未加引号的 `)` 会提前闭合块**
   → `if defined V (echo x (!V!) else (...)` 直接报 `此时不应有 )`，
   整个脚本从该行起崩掉。改为先 `set "PY_VER=not found"` 再无条件 `echo`。

5. **`findstr /c:` 里绝不能放非 ASCII 字面量**
   → 文件被 GBK 解析，UTF-8 中文（如 "USB 串行"）会**破坏整行**，
   cmd 把碎片当命令执行，报一堆 `'local' 不是内部或外部命令`。
   只匹配 ASCII token（Arduino/CH340/CP210/FTDI/USB Serial）。

6. **`for /f` 反引号内的 cmd 元字符必须转义**
   → PowerShell 管道里的裸 `|` 会终止命令替换，报 `此时不应有 |`。用 `^|`。

7. **`for /f ... in ('"某exe" -A x | findstr ...')` 会报
   "文件名、目录名或卷标语法不正确"**
   → 引号 exe 路径在命令替换里被 cmd 弄坏。改成 **先重定向到临时文件再 `for /f usebackq` 读文件**。

8. 🔴 **`if exist "\\.\COM4"` 在本机对所有端口都返回"不存在"**
   → 实测 COM3/4/9/10/19/20/21 **全部 not-openable**（含设备管理器里正常列出的）。
   用它做端口预检会**误拦真板子**。正解：`[System.IO.Ports.SerialPort]::GetPortNames()`
   取列表存成 `,COM3,COM4,`，再 `findstr /c:",COM4,"` 判成员。

9. ## ⚠️ PATH 回退必须做"厂商拒绝"
   本机 PATH 上 **Microchip XC8 的 `avr-objcopy`**
   （`C:\Program Files\Microchip\xc8\v3.10\bin\avr-objcopy`）会被 `avr-objcopy.exe` 命中。
   它属于**另一个编译器家族**（PIC），混进 avr-gcc 链接会产生极难定位的 hex/链接错误。
   已在 `_env.bat` 加拒绝列表（`\Microchip\` / `\xc8\` / `\xc16\` / `\Keil`），
   命中则整组丢弃并留 `REJECTED_CC` 供上层报错 —— 宁可清楚报"请安装"，
   也不静默用一个错工具链。

### 工具链包目录两种布局（都要兼容）
- 扁平：`packages\toolchain-atmelavr\bin\avr-gcc.exe`（本机 `pio pkg install --global` 产物）
- 嵌套：`packages\toolchain-atmelavr@1.7.0\<版本>\bin\...`（旧版 PlatformIO）
取目录时**先探直接子目录再探深一层**；顺序反了会静默命中 `i686-w64-mingw32\` 这种
没有 `bin\avr-gcc.exe` 的兄弟目录。两种布局均已用 mock 目录实测通过。

### 🔴 本轮最关键的坑：`call :label` 是"返回"，不是"终止"
第一版把退出码塞进子例程签名写成 `call :pause_exit <code>`，子例程内 `exit /b %~1`。
**`exit /b` 在 CALL 上下文里只结束这个 CALL，调用处继续往下走**，于是：

- `build.bat` **成功**路径打印 `[OK] build finished` 后，直接**顺序落入**
  `:compile_failed` / `:link_failed` / `:hex_failed` 三个标签，
  连着打出三条 `[FAIL]`，最后退出码被 `:hex_failed` 带成 1。
- `start.bat bogus` 打印错误后**继续跑完整的成功构建**并 EXIT 0。

**正解**（已写入 skill）：**暂停与返回码拆开**——
```bat
call :pause_exit          REM 纯粹等一个按键（内部 exit /b 0）
exit /b <code>            REM 这才是真正结束脚本的那一句
```
并且每个 `:label` 分支末尾必须有自己的 `exit /b`，否则 GOTO 目标会**向下贯穿**到下一个标签。

### 搬家后暴露的 3 个真实 bug（都不是"脚本写错"，是路径推导错了）
| # | 坑 | 症状（非常有迷惑性） | 修法 |
|---|---|---|---|
| 1 | **`shift` 之后再读 `%~dp0`** | `%~dp0` 派生自 `%0`；`shift` 把 `%1` 挪进 `%0` ⇒ 取到项目根。实测 `scripts\build.bat --no-pause` 报到 `MeArm-Device\_env.bat` → `_env.bat` 加载失败 → `PROJ` 全空 → **7 项依赖全报"缺失"**，看着像工具链没装 | 所有脚本开头 `set "BATDIR=%~dp0"` 放在参数解析**之前**，之后用 `%BATDIR%` |
| 2 | **判据层级取错** | `_env.bat` 想验"自己在 scripts 里"，却读 `%~dp0..` 的末段名（= `MeArm-Device`，永不等于 `scripts`）⇒ 守卫恒不成立，`PROJ` 静默停在 `scripts\`，构建误报 `core\main.cpp not found` | 判自身目录名读 **`%~dp0.`**（不是 `..`）；`for %%s in ("%~dp0.") do if /i "%%~ns"=="scripts" ...` |
| 3 | **根+子目录混用但只有一个目录变量** | `start.bat` 在根、`build.bat` 在 scripts\，用同一个 `BATDIR` 必错一半：报 `MeArm-Device\build.bat 不是内部或外部命令` | 区分两个变量：`BATDIR=%~dp0`（自己所在=根）＋ `SCRDIR=%~dp0scripts\`，调用 `call "%SCRDIR%build.bat"` |

### `_env.bat` 工程根推导的最终写法（带布局守卫，放回根目录也能跑）
```bat
set "PROJ=%~dp0"
for %%s in ("%~dp0.") do if /i "%%~ns"=="scripts" (
  for %%d in ("%~dp0..") do if exist "%%~fd\core\main.cpp" set "PROJ=%%~fd"
)
pushd "%PROJ%" >nul 2>nul & set "PROJ=%CD%" & popd >nul 2>nul
```
- `%%~f` 真正折叠 `..`（纯文本截断不折叠，且会残留尾反斜杠污染下游路径）
- `core\main.cpp` 作工程标记兜底
