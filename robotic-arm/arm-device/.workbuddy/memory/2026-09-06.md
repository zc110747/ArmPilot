## 脚本纯英文化 + 摇杆提速修复

### 用户需求
1. scripts 下脚本不能有中文，且目前无法用 PowerShell 直接执行。
2. 摇杆操作运动速度太慢/卡住，需解决。
3. （补充）不要 ps1，仍用 bat，但要保证 cmd 和 PowerShell 都能正常工作。

### 实现
- 全部 5 个 `.bat` 重写为**纯英文 ASCII，无 UTF-8 BOM**（首字节 `40 65 63` = `@ec`）：
  build.bat / build_upload.bat / upload.bat / monitor.bat / clean.bat。
  - 关键：`REM` 注释与 `echo` 全改英文，避免 GBK 控制台解析乱码（之前中文注释导致 PowerShell 下单跑异常）。
  - `.bat` 在 PowerShell 下经 `cmd.exe /c` 直接运行，不受 `Set-ExecutionPolicy` 限制；无 `.ps1`。
  - 已验证：PowerShell 下 `& ".\scripts\build.bat"` 退出码 0（编译通过）。
- 删除上一轮误创建的 `scripts/upload.ps1`（用户明确不要 ps1）。
- 摇杆提速（core/joystick.c `joystick_delta`）：
  - 方向阈值 `>800 / <200` 与原 Arduino **完全一致**，左舵(8) 反向不变。
  - 旧：固定 ±1/20ms → 仅 ~50°/s，主循环 20ms tick 下明显"卡顿"。
  - 新：**比例步进** `step = 2 + beyond/30`（clamp 2..10）°/20ms；轻推慢、硬推快。
  - 仿真验证方向/量纲正确（base 900→-5, left 900→+5, 居中→0）。
- 修了一个真实固件 bug（core/ir_seq.c + joystick.c）：
  - `ir_seq_tick()` 原仅在 running 时消费 `joystick_consume_input()`，idle 时 `g_moved`
    边沿不会被清除 → `JOYHW ON` 浮动 ADC 噪声置位 `g_moved` 后，启动 `SEQ 1` 立即被"摇杆"停掉。
  - 修复：idle 分支也 `joystick_consume_input()` 丢弃陈旧边沿；`joystick_set_enabled(false)`
    时一并清 `g_moved`。
- host_verify.py JOY 用例期望值更新：raw=900 → 5°/次（90→85），反映比例步进（旧固定 ±1 期望 89 已失效）。

### 验证
- 零警告构建；FLASH≈11198B(34.7%)，RAM≈442B（.data=98/.bss=344），栈余量~1606B。
- `avrdude` 烧录 COM4 成功（11198 B verified）。
- `tools/host_verify.py COM4 9600`：**58/58 PASS**（含 JOY 比例步进 5°/次、SEQ 1 启动不被误停、
  JOY 指令停止循环、按钮5 停止、运行中切换等）。

## 红外（IR）动作序列键修复：从"编造码"改为"运行时学习"

### 问题（用户反馈：红外不能正确控制）
- `bsp/ir.c` 解码器本身正确：产生的 32-bit `decodedRawData` 格式
  (`地址<<24 | ~地址<<16 | 命令<<8 | ~命令`) 与原 Arduino IRremote 一致；
- 8 个微调键（左/右/数字2/8/上/下/数字4/6）码 `0xF708FF00…` 是从参考工程照抄的，**正确**；
- **根因**：动作序列键 1/3/7/9(启动)/5(停止) 用的是**编造的 NEC 码**（地址 0xC1/0xC3/0xC5/0xC7/0xC9），
  用户真实遥控器的数字键不会发出这些码 → 序列永远无法触发。
- 序列引擎/串口 SEQ/IR 逻辑本身 OK（host_verify 已验证），只有"遥控键绑定"错。

### 修复（core/ir_ctrl.c + bsp/eeprom.* 新增 + cmd.c）
- 删除编造码；动作集键改为**运行时学习**：`IRLEARN 1|3|5|7|9` 武装，下一次真实红外按键
  绑定到该槽位，写入 **EEPROM**（ATmega328P 1KB，断电不丢），上电自动载入。
  - 1/3/7/9 → `ir_seq_trigger`；5 → `ir_seq_stop`。
- 新增 `bsp/eeprom.c/.h`（`ee_get_u32`/`ee_put_u32`，avr/eeprom.h 封装）。
- 每条硬件红外帧回显 `IR RAW=0xXXXXXXXX`（未绑定回显 `IR ? (unbound code)`），方便真机读出各键实际码。
- 新增 `IRCODES`（查看绑定）、`IRCLEAR`（清除绑定）。
- 抽出公共 `ir_ctrl_feed(code)`：硬件 `ir_ctrl_poll` 与串口 `IR <hex>` 命令**共用**，
  两者都支持学习武装（修了一个 bug：原本只有硬件路径检查武装，串口 `IR` 命令绕过了）。
- `ir_flush()` 新增：IRHW 重新 enable 时丢弃挂起/半帧，避免误重放旧码。

### 验证
- 零警告构建（avr-gcc -Wall -Wextra）：FLASH 12520B(38.8%) / RAM 516B。
- `tools/test_ir_decode.py` 13/13 PASS（解码器对任意合法 NEC 帧正确）。
- `avrdude` 烧录 COM4 成功（12520 B verified，签名 0x1e950f=m328p）。
- `tools/host_verify.py COM4 9600`：**63/63 PASS**（含 IRLEARN→绑定→触发 SEQ、按钮5 停止、
  串口 IR 学习路径、JOY 停止、运行中切换等）。
- 注意：host_verify 末尾 `IRCLEAR` 会清掉本次学习的测试码，设备上电后需用户用真实遥控 `IRLEARN` 重新绑定。

## 红外：真实遥控码写死为出厂默认表

### 用户实测反馈（串口 IR RAW=...）
- 真实遥控 NEC 地址全为 `0x00`，数字键码：
  - 1 → `00FF45BA`  3 → `00FF47B8`  5 → `00FF40BF`  7 → `00FF07F8`  9 → `00FF09F6`
  - 全部校验合法（地址 0x00, `~地址=0xFF`, 命令与反码按位取反一致）。

### 改动（core/ir_ctrl.c）
- 新增 `IR_DEFAULTS[5]` PROGMEM：上述 5 个码按 LEARN_SLOTS 顺序 {1,3,5,7,9} 写死。
- `ir_ctrl_init`：EEPROM 槽若被擦除（`0xFFFFFFFF`）则回退到出厂默认；否则 EEPROM 学习值优先。
- `ir_ctrl_clear_learned`：改为"恢复出厂默认"（RAM 置默认 + EEPROM 写 `0xFFFFFFFF` 标记擦除），
  即 `IRCLEAR` = 还原默认而非置空；重上电仍按默认工作。
- `IRLEARN` 仍可覆盖并持久化（EEPROM 非 `0xFFFFFFFF` 即优先于默认）。

### 验证
- 零警告构建：FLASH 12576B / RAM 516B（.data=132/.bss=384），栈余~1532B。
- `avrdude` 烧录 COM4 成功（12576 B verified）。
- 真机实测佐证：host_verify 运行期间用户按"1"键，设备回显 `IR RAW=00FF45BA` → `OK IRSEQ 1 start (7 steps)`，
  证明默认绑定直接生效、无需 IRLEARN。
- 自动化 host_verify 因用户串口监视器占用 COM4 + 同步按键导致串扰（`拒绝访问`/读值错乱）未能全程跑完，
  非固件问题；IR 默认触发逻辑已由真机按键证实。
- 收尾：`.build/firmware.hex` 已同步为新构建；临时 `.build3` 与日志已清理。
