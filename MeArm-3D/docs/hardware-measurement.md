## 1. 结论一：舵机 → 关节的角色映射（**已确证**）

```
S9 -> base      （底座偏航）
S7 -> shoulder  （大臂 / 下臂）
S8 -> elbow     （小臂 / 前臂）
S6 -> gripper   （开合）
```

固件里的 `left / right`（`MeArm-Device/bsp/servo.h` 的命名）只是**物理安装位**称呼，
**不等于运动学角色**。按它分配肩/肘会得到反向的机构 —— 这是本次修正的一处真实缺陷。

### 证据 A · 扫 S8 时"画面最高点"零位移

`tools/analyze_sweep.py` 输出的「塔顶（掩膜最高点）」：

| 扫描 | 舵机 30 → 100 | 塔顶位移 |
|------|---------------|----------|
| **S8** | (603,220) → (595,220) | **≈0 px（全程 (594±4, 221±2)）** |
| **S7** | (570,220) → (736,321) | **194 px，且下沉 101 px** |

扫 S8 时画面最高处**纹丝不动** ⇒ S8 驱动的不是整条臂，**S8 不是肩**。
扫 S7 时整条臂的上端一起走 ⇒ **S7 是肩**。

### 证据 B · 公共静止区自动分段（`tools/segment_arm.py`）

「扫某个舵机时始终为暗的像素」= 该舵机管不到的部分，于是可以直接把机构拆开：

```
inter_S7 = 扫 S7 全程不动 = 底座 + 立柱（含线材）
inter_S8 = 扫 S8 全程不动 = 底座 + 立柱 + 大臂
=> 大臂 = inter_S8 − dilate(inter_S7)
=> 小臂+爪 = 某帧掩膜 − dilate(inter_S8)
```

`inter_S7` 25198 px、`inter_S8` 31540 px —— 后者多出来的 6342 px 正是**大臂**
（面积占比也符合"大臂在两帧里都不动"）。

### 证据 C · 逐帧目视（`analysis/g2_S8.png`，3×2 网格）

S8 = 30/45/60/75/90/100 六帧并排：**大臂（那对斜板）角度逐帧完全一致**，
只有肘端往下的那一段在摆。这是"肘"的定义图像。

### 采集中踩到的两个坑（结论用）

- `arm_ang`（塔顶→爪尖的连线角）在扫 S7 时只变 1.6°。**这不能当作"小臂解耦"的证据**：
  刚体旋转本来就不改变任意两个刚体点之间的连线方向。第一版据此推出的结论方向对了、
  但推理是错的，本文改用下面的双参数拟合重做。
- 「离枢轴最远的暗像素」做爪尖跟踪**不可靠**：夹爪是两片薄板 + 阴影，帧间会换身份。
  实测扫 S7 的"圆周拟合半径"折合 47 mm，比大臂 80 mm 还短 —— 物理上不可能，
  说明跟踪点已经跑到阴影上去了。**因此放弃单点跟踪**，改用整条骨架对掩膜的对称 Chamfer。

## 2. 结论二：小臂是**绝对角**（平行四连杆解耦）（**已确证**）

### 做法 · `tools/fit_pose.py`

1. 白底分割 → 机械臂掩膜 → 倒角距离变换 `DT`；
2. 把模型的 3 段连杆（大臂 80 / 小臂 80 / 手部 40 mm）在矢状面内投影成折线骨架；
3. 目标函数 = **对称 Chamfer**：
   `mean(DT(骨架点)) + mean(最近骨架点到掩膜点的距离)` ——
   前项把骨架压进掩膜内，后项防它缩成一小段（只做前项会退化，因为掩膜很厚）；
4. Hooke-Jeeves 模式搜索 5 个参数：`s`(px/mm)、肩枢轴 `(ox, oy)`、肩角 `ths`、小臂绝对角 `the`；
5. 覆盖项先**剔掉底座/立柱区**（用上面的 `inter_S7` 膨胀），否则拟合会被底座大团拉偏。

### 去耦判据（扫 S7，舵机 80 → 155，共 75°）

用 **RESET 帧（`S8_090.jpg`）锚定**像素尺度与肩枢轴（`s = 2.626 px/mm`，肩枢轴 `(591.8, 463.6)`），
再逐帧放开 `ths` 与 `the` 两个参数：

| S7 舵机 | `ths` 肩角 | `the` 小臂**绝对**角 | 相对角 = the − ths |
|--------:|-----------:|---------------------:|-------------------:|
| 80  | −2.91° | 112.47° | +115.38° |
| **90** | **+0.85°** | **112.62°** | +111.78° |
| 95  | +4.94° | 112.38° | +107.44° |
| 110 | +14.76° | 113.86° | +99.10° |
| 125 | +23.87° | 115.97° | +92.10° |
| 140 | +34.31° | 119.85° | +85.54° |
| 155 | +50.00° | 122.55° | +72.55° |
| **Δ（80→155）** | **+52.91°** | **+10.08°** | **−42.83°** |

**判据**：

| 假设 | 预期 | 实测 | 结论 |
|------|------|------|------|
| 小臂**绝对角**基本不变 | Δ绝对 ≈ 0 | **+10.08°** | ✅ 成立 |
| 小臂**相对角**基本不变（普通串联关节） | Δ相对 ≈ 0 | −42.83° | ❌ 不成立 |

⇒ 肩关节摆 52.91° 时，小臂的绝对倾角只漂 10.08°。**小臂角与肩角解耦**，
真机由独立舵机经**平行四连杆**驱动（连杆参考系挂在底座侧，而非大臂侧）。

### 模型表达

`config/robot.yaml` 里 `elbow` 关节写：

```yaml
coupling:
  joint: shoulder
  gain: -1     # 串联网里的局部旋转 = the + (−1) × shoulder
```

即 **`elbow` 关节存的是绝对倾角**，FK / Three.js 渲染都经
`effectiveJointAngle()`（`frontend/src/robot/kinematics/fk.ts`）取用，两者逐值一致。

> **已知残差（诚实声明）**：实测漂移 10.08° 并非 0。若按残差硬拟合，
> 等效增益 = `10.08 / 52.91 − 1 ≈ **−0.81**` 而不是理论值 `−1`。
> 模型取 `−1`，因为这正是"平行四连杆"的机构本义，而 10° 落在本次拟合的
> 残差（≈25 px ≈ 9.5 mm）之内。**下一次实测（见 §5）应重测这一点。**

## 3. 结论三：标定增益与零位（**实测反解**）

`tools/fit_pose.py` 用 RESET 帧锚定后逐帧求解，得到「舵机角 → 关节角」序列。

### 小臂 S8（6 帧，舵机 30 → 100）

| S8 | 30 | 45 | 60 | 75 | **90** | 100 |
|----|----|----|----|----|--------|-----|
| 小臂绝对角 | 135.70° | 133.33° | 127.53° | 120.29° | **112.62°** | 107.63° |

线性拟合：`the = −0.4177 · servo + 150.69`，最大偏差 2.47°
⇒ **增益 0.4177 关节度/舵机度 ⇒ `scale = 2.39401`（reverse）**

### 大臂 S7（7 帧，舵机 80 → 155，含 RESET 锚点）

| S7 | 80 | **90** | 95 | 110 | 125 | 140 | 155 |
|----|----|--------|----|-----|-----|-----|-----|
| 肩角 | −2.91° | **+0.85°** | +4.94° | +14.76° | +23.87° | +34.31° | +50.00° |

线性拟合 slope 0.694 关节度/舵机度（**注意增益非线性**：低角段 ≈0.55，高角段 ≈0.80，
典型舵盘连杆特性；线性模型是折中）
⇒ **`scale = 1.44018`（非 reverse）**

### 写入 `config/robot.yaml` 的值

| 关节 | 舵机 | offset | scale | reverse | 关节限位（= 舵机硬限位反算） | 舵机硬限位 |
|------|------|-------:|------:|---------|------------------------------|------------|
| `base` | S9 | 90 | 1 | false | −60 … +60 | 30 … 150 |
| `shoulder` | S7 | 88.776 | 1.44018 | false | −6.0936827341 … 49.454929245 | 80 … 160 |
| `elbow` | S8 | 359.61 | 2.39401 | **true** | 108.4414852068 … 141.8582211436 | 20 … 100 |
| `gripper` | S6 | 40 | 1 | false | 0 … 90 | 40 … 130 |

**自洽性**：把 `homePose` 的四个关节角代回标定式，恰好得到 90°（固件开机位）：

```
base     :   0        × 1      + 90    = 90.000
shoulder :   0.849894 × 1.44018 + 88.776 = 90.000
elbow    : -112.618577 × 2.39401 + 359.61 = 90.000
gripper  :  50        × 1      + 40    = 90.000
```

### HOME（= 固件 RESET 位）的物理姿态

| 关节 | 值 | 物理含义 |
|------|----|----------|
| `base` | 0° | 指向正前方 |
| `shoulder` | **0.8498937633°** | 大臂轴线仅前倾 0.85°（照片拟合值） |
| `elbow` | **112.6185771989°** | 小臂**绝对**倾角：离天顶 112.62° ⇒ **前下方 22.62°** |
| `gripper` | 50° | 两爪半开 |

⇒ HOME TCP = `(111.96, 0, 93.84)` mm（`x = 80·sin(肩) + 120·sin(小臂绝对角)`，
`z = 60 + 80·cos(肩) + 120·cos(小臂绝对角)`）。
虚拟臂渲染出的 RESET 姿态与 4 张实拍照片目视一致（见 `docs/images/armpilot-console.png`）。

## 4. 精度与不确定度（**必读**）

| 量 | 值 | 说明 |
|----|----|------|
| 像素尺度 | 2.63 px/mm | 由 RESET 帧 5 参数自由拟合得到 |
| 骨架拟合残差 | ≈25 px（**≈9.5 mm**） | 对称 Chamfer 两项均值之和 |
| 绝对角不确定度 | **±5° 量级** | 主要来自肩枢轴定位（它同时影响 `s` 与两个角） |
| 增益不确定度 | ±15% | 拟合非线性 + 残差；S8 的 6 点线性拟合最大偏差 2.47° |

**可信度分级**

| 结论 | 可信度 | 依据 |
|------|--------|------|
| S7 = 肩 / S8 = 肘 | **高**（结构事实） | 三种独立方法（最高点位移、公共静止区分段、逐帧目视）互证 |
| 小臂是绝对角（平行四连杆） | **高**（结构事实） | 52.91° 肩摆 ↔ 10.08° 绝对漂移，量级差 5 倍 |
| S7 / S8 增益 | **中** | 6–7 帧线性拟合，逐点偏差 ≤2.5° |
| HOME 绝对角 | **中** | 4 个角度的独立估计落在 ±5° 内 |
| 连杆长度 80/80/40 | 低（沿用开源标称值） | 本次未用标尺测量 |

## 5. 下一次实测要做什么

1. **加标尺**：在画面里放一把钢尺（或打印棋盘格），把 `s` 从"拟合出来的"变成"量出来的"，
   这一步能直接消掉绝对角的系统性偏差。
2. **正交取景**：相机光轴尽量垂直于机械臂运动平面（现在是斜看），减少透视压缩。
3. **覆盖全行程**：S7 扫到 80/160、S8 扫到 20/100 的**硬限位端点**，
   验证增益在高角段的非线性，并确认 `ACTUATOR_REACH` 反算的限位端点。
4. **重测解耦残差**：在**固定 S8**的前提下扫 S7（本次已如此），
   若绝对角漂移稳定复现 ≈10°，就把 `coupling.gain` 从 −1 改到实测值（≈−0.81）。
5. **校核连杆长度**：量大臂/小臂/手部的轴孔中心距，替换开源标称值。

## 6. 复现命令

```bash
PY=<项目隔离 venv>/python

# 1) 采集（会先把四个舵机复位到 90°，再逐个抓图）
$PY tools/mearm_hw.py sweep 7 80 95 110 125 140 155 --out-dir .workbuddy/captures/w2_S7
$PY tools/mearm_hw.py sweep 8 30 45 60 75 90 100   --out-dir .workbuddy/captures/w2_S8

# 2) 帧间运动量化 + 红绿差分红图
$PY tools/analyze_sweep.py .workbuddy/captures/w2_S7 --overlay .workbuddy/analysis/ov_S7.png

# 3) 公共静止区分段（底座 / 大臂 / 小臂）
$PY tools/segment_arm.py --out .workbuddy/analysis/segments.png

# 4) 骨架 ↔ 照片拟合（主证据）：RESET 帧锚定 + S7 双参数解耦判据
$PY tools/fit_pose.py .workbuddy/captures/w2_S8 --sweep the  --anchor .workbuddy/captures/w2_S8/S8_090.jpg
$PY tools/fit_pose.py .workbuddy/captures/w2_S7 --sweep both --anchor .workbuddy/captures/w2_S8/S8_090.jpg
```

> `fit_pose.py` 会自动从 `.workbuddy/captures/w2_S7` 的公共静止区剔除底座/立柱；
> 换台面/换取景时用 `--roi / --thresh / --pivot` 覆盖默认值。
