### 结论：抽象 = **包一层**，不是重做一层

动手前先通读 `RobotModel.ts` / `fk.ts` / `ik.ts` / `buildRobotObject3D.ts` / `gen_model.py`，
确认**现有实现本来就是「一个 Robot Model + 一套运动学」**。缺的只是三样：
① 版本标识 ② 可复现的黄金数据 ③ 一层薄接口。这一步判断决定了后面所有取舍（省掉了重写）。

### 关键发现（写进 `docs/architecture/*.md`）

- **渲染层与 FK 共用 `effectiveJointAngle()`**（`buildRobotObject3D.ts` 直接 import 自 `fk.ts`）
  ⇒ 这是 Phase 3 能到 8.7e-14 mm 的根因，也是抽象层**绝不能复制该函数**的理由（风险 R1）。
- **抽象层"顺手修正语义"会让回归失去意义** ⇒ 所有适配器写成纯字段搬运；
  唯一一处故意严格：`toIkOptions()` 对未知 `prefer` **显式抛错**（`ik.ts` 会静默退化为 `elbow-up`）。
- **`orientationError: null` 而非 `0`**：本机无姿态自由度，填 0 会同时骗过调用方和测试。
- **`defineRobot()` 是视图（对象同一性成立），`forward()` 是新构造结果（只能比内容）** ——
  我一开始用 `toBe` 断言 `forwardKinematics()` 的返回值，2 项失败；改为 `expectSameNumbers()` 逐位比对。
- **`joint.type === 'revolute'` 才是"可动关节"的唯一规则**（不是 `!== 'fixed'`），三端同源。
